# 性能 / Performance

> **English abstract**: DFlash2 K=7 is not a throughput win by default. On a 9-prompt code corpus it is
> +5% mean / +12% median over MTP K=3; on highly predictable content (counting) it is 1.5–1.7×; on
> some code prompts it is 0.82–0.92×. The reason is structural: step time scales with K+1, so DFlash2
> only wins when `AL_dflash > 2 × AL_mtp`. With two Sparks the bandwidth roofline (~546 GB/s) caps
> aggregate throughput — 2× is below the model's per-token expert-byte floor.

## 5. 步成本模型：为什么宽度不是越大越好

| 任务 | 引擎 | AL | tok/s | 步时 | 每验证行产出 AL/(K+1) |
|---|---|---|---|---|---|
| ring | mtp K=3 | 3.19 | 28.7 | ~111 ms | **0.80** |
| ring | mtp K=7 | 2.48 | 23.8 | ~150 ms | 0.31 |
| ring | DFlash2 K=7 | 2.28 | 26.3 | ~98 ms | 0.29 |
| py_api | mtp K=3 | 3.53 | 45.0 | ~78 ms | **0.88** |
| py_api | mtp K=7 | 6.00 | 39.2 | ~153 ms | 0.75 |
| py_api | DFlash2 K=7 | 4.67 | 48.1 | ~90 ms | 0.58 |
| count | DFlash2 K=7 | 7.05–7.52 | 75.6 | ~90 ms | 0.88–0.94 |

两个结论：

1. **步时 ≈ 行数 × 每行成本**（每行约 18–26 ms），投机器不改变步成本，只改变每步产出多少 token。
2. 所以净收益的判据是 `AL/(K+1)`，不是 AL 本身。

判定式：

```
DFlash2 赢 mtp K=3  ⇔  AL_dflash/(7+1) > AL_mtp/(3+1)  ⇔  AL_dflash > 2 × AL_mtp
```

本机 mtp 的 AL 是 2.2–3.5 → DFlash2 需要 AL > 4.4–7.0。这是「内容可预测性」的函数，不是参数问题。

## 6. 带宽 roofline：为什么两机做不到 2×

- 2×GB10 峰值带宽 ≈ 2 × 273 GB/s = **546 GB/s**
- 45 层中 42 层 MoE，288 专家/层，每 token 选 8 个；单专家 3×4096×2048 ≈ 25.2 M 参数，
  NVFP4（含块缩放）≈ 0.56 B/参数 → **14 MB/专家**
- 8 个专家全不重复：42 × 8 × 14 MB ≈ **4.7 GB/token**（模型自身下限）

实测对账：

| 配置 | c8 tok/s | 折算每 token 专家字节 |
|---|---|---|
| mtp K=3 + py_api | 128.5 | 4.26 GB（≈ 下限的 91%） |
| DFlash2 K=7 + py_api | 125.1 | 4.37 GB |
| mtp K=3 + ring | 78.6 | ~6.9 GB |
| DFlash2 K=7 + count | 210.7 | 2.6 GB（高接受率 → 专家复用率高） |

2×（157 tok/s @c8）要求 < 3.5 GB/token，**低于 4.7 GB/token 的自身下限**。所以：
不加卡、不降比特、不降 experts，2× 不可能。能达到的最高聚合吞吐是「AL 拉满」时的 210 tok/s，
典型负载的上限在 116–130 tok/s。

## 7. 负面结果（省得别人再试一遍）

| 尝试 | 结果 |
|---|---|
| MTP K=7（同一 head 递归，不换 drafter） | 全档更慢：21.6/29.5/42.2/62.5（c1/2/4/8），0.68–0.80× |
| 关掉投机解码（plain decode） | ring 25.7/38.0/56.3/76.9，比 K=3 低 12–74% |
| A8 激活（`VLLM_B12X_MOE_FP4_FORCE_A16=0`） | 崩到 14 tok/s |
| SGLang 跑 GLM-5.3 | SM121 上没有可用 DSA attention 后端，起不来 |
| MTP + DFlash2 混合路由 | 该 fork 的 SpeculativeMethod 是单值，不支持；SGLang 的 hybrid 在这硬件上不可用 |

## 8. 结论

- DFlash2 的价值是**延迟**（TTFT 63→25 ms）和**高可预测内容的吞吐**（1.5–1.7×），不是通用吞吐。
- 通用 code 想提速，方向不在投机宽度，而在每步成本（kernel / 量化）或更多卡。
- 两机 TP2 已经踩在 roofline 上，继续调参只有 ±15%。
